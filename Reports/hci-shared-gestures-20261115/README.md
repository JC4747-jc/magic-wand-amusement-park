# 共用火机手势：编辑器验证

火机与六类 Park 内容共用 TabletopHandSample 关节采样/伸展比例判定、TabletopGestureRules 四维仲裁和 GestureReachWindow 距离门控。实际 XR 回调只消费新鲜右手 Dynamic 关节数据。A 捏合释放、B 食指画圈、C 张掌横挥、D 握拳后张开；不同对象只在动作层解释四个维度。

共享测试在保存的 ParkPlant 场景进入真实 Play Mode，依次加载六类内容，以合成关节派生帧调用生产入口 ProcessHandSample。24 条 A/B/C/D 轨迹与火机规则一致且动作被接受；UI/空间确认、丢失目标、过期采样、远距输入均阻止施法，静止掌与竖直挥动不触发额外魔法，长握拳不再抢占为 Undo。标定要求两次独立捏合，持续捏合不能同时确认底部和顶部。原 TabletopGestureChecks 同轮通过。

植物、猫狗梦境、六场景既有动作流程及 14 个原场景启动另行回归，结果见子目录。六场景/启动回归只证明相应范围，不证明八用例 32 项全部完成。所有重任务串行、沿用资源守卫；资源数据为 5 秒采样，不是连续峰值。

首次启动检查在审计阶段失败：旧规则要求场景数恰好 14，但工程另外保留两个森林试作。审计改为逐名确认 14 个必需场景，仍检查全部发现的场景是否缺脚本；启动检查仍运行明确列出的 14 个集成场景。首次失败信息保留，没有删掉试作或跳过缺脚本检查。

正式目标仍为：YOLO 识别现实物体 → 可靠定位/选中 → 共用火机手势 → 对象对应魔法 → 撤销/复位。现有 ParkStereoReceiver 有类别/置信度/时效/双目深度门控；本报告未重新验证其真实 YOLO 相机链路。Virtual Test 与键盘只是调试入口。房间平面和天花板仍需真实确认，不能从家具框推断。

限制：没有真实 XR/PICO 关节、YOLO 端到端、Android 重构建或 HCI 实验记录闭环验收。此批运行时代码仍为本地候选，未发布到 restore-4d-lighter；远程已交付基线是 cba8ffb。隔离工程保留猫步态 v2 候选，与主工作区猫 FBX 不同，本报告不证明正式猫模型动画。manifest 绑定列出的源码，不代表整个隔离工程与主工作区字节一致。
