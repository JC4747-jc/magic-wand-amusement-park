# Park 真实手势采样入口

六个保存的 Park 场景可在既有的双目录制中附加手势日志。设备的应用私有数据目录须同时有 `record-stereo.enabled` 和 `record-hands.enabled`，且 Park 双目相机已启动。每段记录为对应 `stereo-replay-*` 目录内的 `hand-samples-*.jsonl`，停用虚拟模式采样。日志保留 Dynamic XR 样本的有效性、掌心、食指和拇指、手指伸直率、捏合距离、头显横轴、目标距离、UI 与摆放门控、识别及派发结果。现行识别阈值沿用发布基线。

每条记录绑定最近一次已写盘的原始 PICF 回包，保留帧号、采集时间戳及距回包写入的秒数。它用来关联发生在回包之后的手势，两个采样流频率不同。未写入回包时绑定字段是显式缺失值。每段最多 6,000 条、8 MiB 或 120 秒，按最先到达的上限停止。暂停、退出及录制 I/O 失败时关闭句柄。手势日志只写本机。

Unity 6000.0.33f1 实际编译后打开六个 Park 保存场景和 BridgeStereoFusion，检查组件绑定。合成调用验证双开关、有效与无效样本序列、错误帧号无绑定、同帧原始回包、JSON 字段、关闭与三项容量限制。极限测试保留 6,000 行，超大字段对照在 8,385,590 字节停止，时间到期关闭并写出此前的一行。[Unity 结果](native-v4/result.txt) · [合成样本](native-v4/synthetic-hand-samples.jsonl) · [资源限制结果](native-v4/trace-limits.json)

阶段中先修正了隔离启动器的路径传参，随后修正了 Unity 程序集引用方向。复测最低采样可用内存 6.68 GiB，进程树最高采样 RSS 1,461.07 MiB，候选盘阶段最大采样净增 12 MiB。1,840 项隔离项目源文件和主仓库索引已按哈希恢复。[资源记录](native-v4/resources.json) · [恢复回执](native-v4-restoration.json)

本次验收范围是 Unity 源码和合成记录。设备上的文件采集、真实 YOLO 与实际手势、暂停后重开、落盘耗时和帧率仍需 PICO 核对。
