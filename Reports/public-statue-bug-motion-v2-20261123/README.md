以同类且 IoU≥.50 判定定位。v16 回包和计分门槛为 .65，其他两种回包从 .399 开始，计分 .50。模型只按配置类别给回包，单类候选在无对应类的片段用于核查误触发。原片标注框宽均超过 64 px。半尺度对照里四帧蟑螂宽小于 64 px，均漏检。整帧的持续漏检也出现在大于 64 px 的目标上。两段跳蛛取自同一视频，片段数不能视为独立动物数。[逐帧分数、图框和耗时](result.json) · [目检对照](review.jpg)

v16 把移动中的机器人连续四帧判为 Cockroach，均为同一 ID，置信度 .757–.943，首尾回包约隔 711 ms。在原回包上加 .85 门槛，仍有连续三帧同一误报，所以仅靠三帧确认无法拦住这个案例。双类权重的跳蛛在 .399 时有前后两次连续三帧命中，中间漏三帧；相距 1,149 ms 后恢复原 ID。在 .50 时仅后面三帧计入。正常速度的蟑螂片段含视频剪切，结果不能用于衡量同一动物的跨剪切稳定性。[原始 ID 和阈值复算](track-audit.json)

重放沿用媒体抽样间隔，并顺序等待回包。服务慢于抽样间隔时，以真实请求时间差判断 ID 恢复。热态 CPU 每组中位 32.79–37.09 ms（双类）、203.74–210.72 ms（v16）、210.90–221.33 ms（OIV7m）。最低采样 RAM 7.09 GiB，任务最高 RSS 1,351.17 MiB，有界运行约 65 秒，资源保护未触发。首次回放在旧 v16 元数据缺少新字段时停止，修正后统一复跑。只做 PC 回包与身份检查，现场摄像头、Android、PICO 和 A/B/C/D 仍待验证。[资源](resources.json)
