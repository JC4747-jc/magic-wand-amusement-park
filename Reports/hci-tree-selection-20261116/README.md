# HCI 树木体验选择入口验证

共享界面此前仅在 Virtual test 显示 Natural tree / Fantasy tree，导致正式 Tree 目标不能从共享菜单选择四季树或打人柳。本次将两个按钮标为 **Four seasons / Whomping willow**，选中且追踪有效的同一 Tree 可选择体验；当前选择高亮，状态栏显示体验。选择是内容导航，不是 A/B/C/D 施法，不创建或替换现实目标，也不自动生成识别结果。

## 运行与输入

Tree 识别和可靠定位后，以既有指向/捏合选中目标，在共享菜单选择体验；保持实物位置、朝向和尺寸拟合，清除上套体验效果及原环境表面确认，张手准备后再施法。四季树与打人柳始终共用火机的 A 捏合松开、B 指尖画圈、C 张掌横挥、D 握拳张开。虚拟 Test awaken 按钮在实体目标分支隐藏且 API 拒绝执行，Replay 不允许更改该选择。

选择 API 检查所属控制器注册实例、Tree 场景、追踪新鲜度、活动状态与虚拟/实体模式一致性；动画忙、Fit/Plane 未结束、丢失/过期/禁用/外来实例时拒绝切换。成功切换重置手势所有权，UI 捏合释放不能成为 A；反复选当前体验不重置 Revision。旧 TreeMode 入口改走同一保护 API，虚拟预览 API 继续保留。

## 验证证据及范围

Unity 6000.0.33f1 的保存 ParkTree 场景分别执行实体目标代码分支的四季树/打人柳流程，再回归原虚拟两套流程、六类内容 24 条共用手势和四实验条件矩阵。实体目标分支的输入来自明确标注的合成 Observe 坐标；测试关闭断开连接的硬件接收器以隔离输入源，仍执行控制器注册、过期与真实目标代码分支。它不是实际 YOLO/深度/头显识别结果。第一轮因未隔离接收器，被正式断连保护正确清除，测试修正未放宽生产保护。

两套流程通过共用 ProcessHandSample 与火机规则逐次比对，检查一次动作一次接受、完整 A/B/C/D、前置条件、撤销、复位及定位不变。新增 synthetic-events.csv 具有 SYNTHETIC 身份和来源声明，记录内容选择事件以及施法对应的 experience 字段；不能当作受试者数据。PNG 为实际 Unity 渲染，manifest 绑定源文件与资源守卫结果。

六个重任务串行运行，保留暖 Library；启动至少 6 GiB 可用 RAM，运行下限 3 GiB、Editor RSS 上限 3.5 GiB、C/D 盘最低 20/25 GiB、单任务 C 盘增长 1 GiB、日志 16 MiB、15 分钟超时。报告为五秒采样而非连续峰值。未启动训练、模型下载或重启；新增训练/下载授权和保护要求同时保存于 BRANCH_SCENE_PLAN.md。
