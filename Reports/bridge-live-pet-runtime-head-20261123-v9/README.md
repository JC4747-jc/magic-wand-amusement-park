# ParkPet 同帧头位运行时候选

从保存的 BridgeStereoFusion 打开 ParkPet。原 PICF YOLO 路径先处理真正由 Unity 编码的左目 JPEG，原接收器用同次采集的左右灰度定位身体。候选步骤在原共享点捏选中猫后启用。它从该次采集裁取左右原图，使用当前身体视差限定右眼搜索，交给独立的头位服务。头位响应核对会话、帧号、时间戳和 ID，再按发送时保留的相机与头显位姿投影。该服务保持单请求在途，Unity 根据采集时间执行 300 ms 空间时限。

Unity Editor 声明为桌面回放，左右图来自已标定真拍，同一次送入运行时绑定，位姿和点捏由夹具提供。PC 用本地猫候选 YOLO11s 在 CUDA 上推理，头部 AP-10K 在独立 CPU 进程执行。正式检测器权重、保存场景与 Android 包没有更改，头部端口默认关闭。

| 运行结果 | 观测 |
| --- | --- |
| 身体和选择 | 源帧 30–32 通过三次身体观测，再由共享点捏选中同一 Cat ID |
| 头部挂接 | 第 5–7 条真实 PICF 绑定的回复在 165–208 ms 被接受，三次确认后挂接；头部约 1.461 m，原片左目鼻尖附近 LiDAR 约 1.537 m |
| 超时和恢复 | 第 8 条请求故意延时，客户端报告 deadline 并清除头位。第 9–11 条新回包在约 157 ms 被接受，三次确认后重新挂接同一 ID |
| ID 切换 | 第 12 条回包报告不同 ID，旧头位不再可用，新实例首帧保持无头位 |

试验按约 5 Hz 供帧，场景保存的发送上限仍为 10 FPS。CPU 检测尝试曾产生超过 300 ms 的回复；改用有界图块后，最终通过的是本机 CUDA 检测和 CPU 头位的组合。源帧 30 的实际 JPEG 同时产生 Cat 与 Dog 框，未选择时歧义门槛拒绝头位请求。测试保留该门槛，由共享点捏明确目标后才附着头位。PICO 原始输入、无线总时延和现场接触仍待验。

关闭头位端口后以正式 YOLOv8n 复跑犬用例，收回 44 条实际 PICF 回包，共享合成 A/B/C/D、短时失跟、同 ID 恢复和 Reset 通过。已目检梦境泡画面。[关闭端口的轨迹](default-dog-trace.txt) · [梦境泡画面](default-dog-agency.png)
