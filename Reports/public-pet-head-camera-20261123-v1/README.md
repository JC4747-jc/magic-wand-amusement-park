# 萌宠头位：相机输入与 CPU 延迟

冻结真实 YOLO 回包、身体框、视差和 AP-10K 权重，重算 57 对有可用输入的鼻眼结果。双彩色对照的位置误差低于 0.01 px，逐帧门控结果与前一轮一致。JPEG 95 重编码逐帧复现原 PICF 回放所用左图的哈希。场景 `ParkPet` 使用 JPEG 90，软件回放用 OpenCV 近似其压缩，并以与 PICO 捕获代码相同的整数公式生成右图灰度。纹理匹配使用未压缩灰度对。

- 左图 JPEG 90、右图灰度组保留同一犬 ID 第 32–35 帧连续通过，第 34、35 帧输出三帧确认。右鼻尖比人工坐标相差 1.0–2.2 px。第 174 帧的单次命中消失。犬头 LiDAR 仍无可用独立距离。
- 独立弗赖堡数据中，12 帧头部不可见样本均未通过。人工身体框的 5 帧可见样本在双彩色对照中全部通过，左 JPEG 配右灰度减少至 3 帧，三帧确认输出从 3 次减至 1 次。把右图恢复为彩色，5 帧均通过。默认 YOLO 在该可见组仅一帧有可比较输入，所有格式均无确认。
- 公制猫的默认 YOLO 仍无头位确认。候选猫的 JPEG 90 两组只保留第 32 帧的确认，右灰度组约 1.476 米，LiDAR 约 1.537 米。第 251 帧虽通过单帧门控，前序不足三帧。

## CPU 推理

57 对、4 种输入共 228 次双眼推理，单线程中位数 147.1 ms，P95 158.6 ms。另以犬 4 对、候选猫 2 对和独立背脸 2 对做预热后的比较，每种配置测 16 次。

| 线程数 | 两眼执行方式 | 中位数 | P95 |
| --- | --- | ---: | ---: |
| 1 | 顺序 | 146.5 ms | 154.6 ms |
| 1 | 批量 | 142.9 ms | 149.8 ms |
| 2 | 顺序 | 84.0 ms | 85.9 ms |
| 2 | 批量 | 86.5 ms | 91.8 ms |

四种配置的关键点峰值位置和分数张量一致。耗时只涵盖两眼 AP-10K 推理，后续需要实测同帧 YOLO、传输和 Unity 门控的总时延。在当前场景的 10 FPS 发送上限、300 ms 空间结果时限下，仍需复验更新频率、旧结果丢弃、失跟与恢复。本轮工作未接入 Unity 生产头位，也未进行 PICO 真机验证。

两次有界运行最低采样可用内存 8.40 GiB，最高任务进程组内存约 153 MiB。相机输入结果文件约 487 KiB。资源保护未触发。
