# 石像手势、丢失与重新选择

从保存的 BridgeStereoFusion 菜单点 Statue，进入原 ParkStatue。Unity 测试将原项目 PC 服务的 203 条 PICF 回包按原字段值送入场景保存的 TCP 与 ParkStereoReceiver，使用已标定的 640×480 实拍图。测试位姿、手部关节、模型尺寸与 D 的水平面由检查脚本提供。识别输入来自同一件石像的固定照片以及一组无检测回包的对照照片。[标定和来源](../statue-calibrated-depth-20261123/README.md) · [PC 回包](picf-timeline.json)

每组关节轨迹与火机共用的手势规则逐样本对照。每次仅触发一个动作，保持末姿未重触发。第二次 C 在许愿树还显示时重新打开卷轴，用于验证丢失事件同时清理卷轴、许愿树和水平面。

短丢失为 3 个无目标回包。PC 下一次返回原实例 ID，Unity 连续三次认可位置后恢复同一选择，旧效果已清除，新的 A 可再次触发。长丢失为 15 个无目标回包。新 ID 没有接管旧选择，等旧锚点释放后才通过点选捏合选中，新的 A 可触发。[Unity 轨迹](trace.txt) · [输入清单](input-v6.json)

PC 首轮的 5 个无目标回包仍保持同一 ID，后按实际服务的 1.5 秒保持规则设置短、长两组丢失。Unity 前几轮修正了检查脚本选错类、合成关节送帧时机和 B 的施法转场等待。第 5 轮通过交互断言，目检发现卷轴和园景被裁切，第 6 轮按可见几何重新取景。场景运行源码沿用 `4d40be0` 的资产内容，隔离项目每轮按文件哈希复核恢复。各轮资源保护均未触发，最低可用 RAM 采样 6.50 GiB。最终轮最低 6.56 GiB，任务树最高 RSS 采样 1,685 MiB，D 盘任务期间无采样净增。[最终检查资源](unity-resources.json) · [PC 资源](picf-resources.json)
