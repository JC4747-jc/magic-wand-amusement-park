# Bridge 萌宠头位：真实编码、时延和身体门槛

保存的 BridgeStereoFusion 进入 ParkPet，Unity 原发送器以 JPEG 90 编码并按 10 FPS 上限发送。每次使用实际 PICF v2 的帧号和时间戳，PC 原 YOLOv8n 服务处理同一 JPEG。独立试验服务用解码画面的缩略图核对左右帧配对，再对左 JPEG、右灰度运行鼻眼推理。右眼搜索窗口复用同一原始帧上已核对的身体视差。Unity 原接收器根据本次实测检测框自行完成身体测距。桌面只供给图像和位姿，头位候选由模型与真实纹理计算。

| 试验 | 第 33 帧结果 | 头部挂接 |
| --- | --- | --- |
| 发布配置，YOLO IoU 0.70 | 同一只犬输出两个框，两框 IoU 0.694，较小框的 99.9% 被较大框覆盖。目标 ID 分裂 | 未建立连续确认 |
| 试验 IoU 0.65 | 保留分数略高的短框，头位证据存在，身体双目有效补丁不足 | 保持关闭 |
| IoU 0.70，加试验用重复框消歧 | 保留完整犬框。源帧 32–35 两次经过同一 ID，所有四帧均通过鼻眼与单帧身体门槛 | 第 33→34 帧的身体位置跨 14.2 cm，超过原三帧身体确认的 12 cm 距离门槛，身体未进入可交互跟踪 |

第三次运行八帧的端到端年龄为 200–254 ms，约 4–5 次每秒。插入 330 ms 延时后，有有效头位证据的回包在 549 ms 到达，原接收器将其降为仅识别。第 150 帧重新取得身体测距，脸部几何不一致，头位候选仍关闭。三次完整的自动头位挂接断言均未通过。可证明按原门槛没有误挂接，已挂接头位的清除与重建本轮缺证据。

实际编码下的重复框已目检。保留完整框的方法仅限同一犬的这个片段。下一次需先用更长的真实连拍取得原门槛认可的同一身体 ID，再覆盖头位分配、失跟和恢复。还需用不同个体和重叠多犬验证重复框处理。两种试验均未接入生产，正式配置和 APK 未变。

三轮资源保护均未触发。最低采样可用 RAM 5.78 GiB，候选盘最大采样净增 1 MiB。候选工程的 1,840 项输入与主工作区 Git 索引均已复核恢复。
